# 小程序会员错误处理修复设计

## 目标

修复会员体系上线前发现的两项错误处理问题，不改变会员判断、邀请规则、计费逻辑或页面布局。

## 方案

1. 视频提交接口返回 `403 membership_required` 时，全局请求层继续负责展示统一会员弹窗；视频页面识别该错误后只结束忙碌状态并立即返回，不再显示“修改初始密码”。其他普通 `403` 保持原有提示。
2. 邀请中心并行读取邀请码、统计、奖励和推荐人四个接口。四个响应都必须为 `200`；任何一个失败都进入现有错误状态，不写入默认的零值或空记录。

## 错误处理

- 会员错误只展示一次统一弹窗，避免相互矛盾的页面提示。
- 邀请数据读取失败时使用对应接口的 `detail`；没有服务端文案时使用明确的本地读取失败文案。
- 网络异常继续由现有 `catch` 处理。

## 测试

- 增加视频源代码契约测试，确保会员错误判断位于通用 `403` 分支之前并立即返回。
- 增加邀请页面行为测试，模拟奖励接口失败，确认页面进入错误状态且不把奖励显示为 `0`。
- 运行全部小程序 Node 测试、JavaScript 语法检查和 JSON 解析检查。
