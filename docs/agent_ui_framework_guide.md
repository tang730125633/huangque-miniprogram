# 黄雀 Agent UI 组件框架接入指南与示范内容规范

> **核心设计定位**：这是一个**专为 Agent 量身打造的 UI 组件驱动框架**。前端小程序仅作为符合 Apple HIG 规范的高保真纯矢量通用渲染容器（Container & Engine），**前端代码中不硬编码任何业务文字、卡片数量或流程逻辑**。Agent 后端只需下发标准 JSON Schema 数据包，前端即可自动渲染并处理交互与指令回传。

---

## 一、 框架整体工作流程

```
┌────────────────────────────────────────┐
│             后端 Agent 核心            │
│  (LLM 推理 / 工具流 / 业务规则引擎)    │
└──────────────────┬─────────────────────┘
                   │
                   │ 1. 下发任务结构与组件卡数据包 (JSON Schema)
                   ▼
┌────────────────────────────────────────┐
│        黄雀 Agent UI 组件框架          │
│        (微信小程序 / Web 仿真端)       │
│                                        │
│  - 动态任务胶囊栏 (#TASK 编号/标题/计数)│
│  - 动态组件卡片系统 (单选/多选/采集/动作)│
│  - Apple HIG 纯矢量原生渲染 (SF Symbols)│
│  - 适老化 44pt 大触达与长文本展开/收起  │
└──────────────────┬─────────────────────┘
                   │
                   │ 2. 用户点选 / 批量勾选 / 动作按钮触发
                   ▼
┌────────────────────────────────────────┐
│          标准化用户指令回传            │
│  例:【点选】门店引流口播文案：A版...   │
│  或: { mode: "record", prompt: "..." } │
└────────────────────────────────────────┘
```

## 二、 Agent 下发 JSON 数据契约 (Schema 规范)

Agent 在回复消息时，若需要呈现交互组件，只需在响应体中提供 `task` 与 `widgets` 字段：

```json
{
  "task": {
    "id": "TASK-8902",
    "title": "视频制作方案准备就绪",
    "desc": "门店引流文案 · 配音音色 · 数字人形象",
    "collapsed_desc": "方案已收起 · 点击展开 3 项组件卡"
  },
  "widgets": [
    {
      "id": "script_pick",
      "type": "script_pick",
      "title": "门店引流口播文案",
      "hint": "点一下选一版，选好后自动进入下一步",
      "selection_mode": "single",
      "selectedId": "script_1",
      "items": [
        {
          "id": "script_1",
          "title": "A版 · 直给福利型（福利直给）",
          "summary": "福利直给",
          "body": "“店里周年庆，老板发话直接让利！全场招牌套餐立减30元，只要来店报暗号‘黄雀’再送甜品一份，仅限本周前50位！”"
        }
      ],
      "actions": [
        {
          "label": "＋ 重新生成一组文案",
          "prompt": "请根据刚才的要求换一个风格重新写一组口播文案"
        }
      ]
    }
  ]
}
```

### 字段说明一览表

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `task.id` | string | 任务编号（如 `TASK-8902`），前端自动提取展示为 `#8902` 标签 |
| `task.title` | string | 任务主标题（如 `视频制作方案准备就绪`、`多渠道推广计划`） |
| `task.desc` | string | 任务展开时的概览副标题，缺省时自动串联所有卡片标题 |
| `task.collapsed_desc` | string | 任务收折时的提示语，缺省时自动计算 `方案已收起 · 点击展开 N 项组件卡` |
| `widgets[].id` | string | 组件卡唯一标识符（如 `script_pick`、`voice_pick`、`custom_card`） |
| `widgets[].type` | string | 卡片类型：`script_pick`（文案）、`voice_pick`（音色）、`avatar_pick`（数字人）、`voice_sample`（录音采集）、`option_pick`（通用卡） |
| `widgets[].icon` | string | 可选。自定义图标路径或 URL，缺省时自动匹配 SF Symbols 图标 |
| `widgets[].title` | string | 卡片标题（如 `门店引流口播文案`） |
| `widgets[].hint` | string | 卡片辅助说明（如 `点一下选一版，选好后自动进入下一步`） |
| `widgets[].selection_mode` | string | 选择模式：`"single"`（单选，Radio）或 `"multiple"`（多选，Checkbox） |
| `widgets[].min_selected` | number | 多选时的最少勾选数，默认 `1` |
| `widgets[].max_selected` | number | 多选时的最多勾选数，默认无限制 |
| `widgets[].selectedId` | string | 单选时当前选中的选项 ID |
| `widgets[].selectedIds` | array | 多选时当前已选中的选项 ID 数组 |
| `widgets[].items` | array | 选项列表，详见下文 items 规范 |
| `widgets[].actions` | array | 卡片底部的动态操作按钮（如重写、克隆、定制等） |

## 四、 前端交互如何向 Agent 回传指令

当用户在前端界面操作时，组件框架会自动构建纯净的自然语言协议指令并发送给 Agent：

1. **单卡点选**：
   * 指令格式：`【点选】卡片标题：选项主标题（id=选项ID）`
   * 用户气泡展示（适老化友好）：`A版 · 直给福利型`（不露出技术参数）
   * 传给 Agent 提示词：`【点选】门店引流口播文案：A版 · 直给福利型（id=script_1）`
2. **多卡全选齐后自动提交 / 点击「确认选择」**：
   * 指令格式（合并多行）：
     ```
     【点选】门店引流口播文案：A版 · 直给福利型（id=script_1）
     【点选】配音音色定制：温柔知性女声（id=voice_1）
     【点选】数字人形象选择：晓晴（id=avatar_1）
     ```
3. **点击动作按钮（Action Button）**：
   * 直接发送 `action.prompt`（例如用户点击 `[＋ 重新生成一组文案]`，直接向 Agent 发送 `"请根据刚才的要求换一个风格重新写一组口播文案"`）。
